# GitLab MR Radar

Chrome-расширение (Manifest V3) для любого GitLab-инстанса (gitlab.com или self-hosted). Показывает в popup открытые MR, которых не хватает в дашборде GitLab Free, и выводит счётчик на иконке.

## Секции

| Секция | Что попадает |
|---|---|
| Меня назначили ревьюером | Открытые MR, где я в reviewers (кроме своих). Если уже апрувнул — помечается тегом |
| Ждут моего апрува | Открытые не-draft MR в проектах, где у меня Maintainer+, не мои, без моего апрува, и где я не ревьюер |
| Ждут моего ответа в тредах | Мои MR и MR на ревью, где есть нерешённый тред, в котором я участвую (или MR мой), а последний комментарий не мой |
| Мои MR | Мои открытые MR: число апрувов, merge-статус, треды |

Счётчик на иконке — число уникальных MR, требующих действия: ревью без моего апрува (не draft) + ждут моего апрува + ждут ответа в тредах.

## Установка

1. Скачать `gitlab-mr-radar-<версия>.zip` со страницы [Releases](../../releases) и распаковать (или склонировать репозиторий).
2. `chrome://extensions` → включить **Developer mode** → **Load unpacked** → выбрать распакованную папку.
3. Открыть настройки расширения (⚙ в popup):
   - **GitLab URL** — `https://gitlab.com` или адрес своего инстанса (только https), в точности как в адресной строке GitLab — иначе ссылки в popup будут вести на главную. При сохранении Chrome попросит доступ к этому хосту — без него расширение не работает;
   - **Personal Access Token** — scope **только `read_api`**, обязательно со сроком действия (ссылка на создание токена появится под полем);
   - интервал обновления.
4. Опционально — ограничить проекты для секции «Ждут моего апрува»: режим «Только выбранные» → «Загрузить проекты». Проекты показываются деревом по группам; чекбокс группы (включая корневую) выбирает или снимает все проекты внутри. Есть фильтр по пути. MR, где я ревьюер или автор, показываются из всех проектов независимо от фильтра. Новые проекты в режиме «выбранные» не подхватываются автоматически.

Если GitLab недоступен (нет сети/VPN), на иконке `!`, в popup — причина.

## Как устроено

- `src/gitlab.js` — REST API v4: список проектов с `min_access_level=40`, MR по проектам, `/approvals` и `/discussions` по каждому MR (discussions — только для моих MR и MR на ревью, где `user_notes_count > 0`). Используются только эндпоинты Free-тира.
- `src/background.js` — service worker: обновление по `chrome.alarms`, результат в `chrome.storage.local`, бейдж.
- `src/popup.*` — рендер из storage, кнопка ручного обновления.
- `src/options.*` — URL, токен, интервал, выбор проектов.

## Безопасность

- Доступ к хостам запрашивается в рантайме (`optional_host_permissions`) только для указанного GitLab; при смене URL доступ к старому хосту отзывается.
- Токен хранится в `chrome.storage.local` (не синхронизируется между устройствами) и отправляется только в заголовке `PRIVATE-TOKEN` на указанный хост.
- Popup строит DOM только через `textContent`, ссылки открываются только внутри указанного GitLab.

## Обновление

Скачать новый релиз и заменить папку, затем кнопка ↻ у расширения на `chrome://extensions`.
